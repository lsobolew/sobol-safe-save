# WP Plugin Lab

A repository that contains `bin/wpx`, `wp-matrix.json` and `starter.json` is a WP Plugin Lab
project: a WordPress plugin plus the environment that develops and tests it.

## The one rule that matters most

**PHP only exists inside the containers.** Never suggest `composer`, `phpunit`, `phpcs`, `phpstan`
or `wp` as host commands - they will not be there. Use the `wpx` commands, or drop into a container:

```bash
./bin/wpx sh latest -- 'cd /var/www/html/wp-content/plugins/<slug> && vendor/bin/phpcs'
./bin/wpx wp latest -- plugin list
```

Node and Docker are the only host requirements.

## Orientation

```bash
./bin/wpx              # every command, with one-line descriptions
./bin/wpx doctor       # is this machine ready, what is configured
./bin/wpx status       # which WordPress versions are running, on which ports
./bin/wpx matrix       # what latest/latest-1 currently resolve to
```

Read `starter.json` (plugin identity, editions, features, skills, lab source) and `wp-matrix.json`
(WordPress versions, themes) before changing anything - they drive everything else.

## Daily loop

```bash
./bin/wpx up latest              # or `up` for every version in the matrix
./bin/wpx dev                    # rebuild blocks on save (TypeScript + Vite)
./bin/wpx test unit --targets=latest
./bin/wpx panel                  # dashboard on 127.0.0.1:7777
```

Plugin sources are bind-mounted, so an edit on the host is live on every running version at once.
There is no deploy step.

## Testing

| Suite | What it proves |
|---|---|
| `unit` | Pure logic, WordPress stubbed with Brain Monkey. Sub-second. |
| `integration` | Real WordPress core test suite: post types, meta, REST, capabilities. |
| `e2e` | Playwright in a real browser, including blocks in the real editor. Runs once per theme in the sweep. |
| `types` | `tsc --noEmit` - Vite only transpiles, so nothing checks types without this. |
| `lint` | PHPCS with WordPress Coding Standards and PHPCompatibility. |
| `analyse` | PHPStan level 6. |
| `plugin-check` | The WordPress.org reviewers' own tool. |

```bash
./bin/wpx test                                   # unit + integration + e2e, everywhere
./bin/wpx test lint analyse types --targets=latest
./bin/wpx test e2e --targets=latest --edition=both
./bin/wpx test integration --targets=latest,min  # newest and oldest - where bugs show up
```

Results land in `.wplab/results/*.xml` and feed the dashboard.

**Before calling any change done**, run at minimum:

```bash
./bin/wpx test lint analyse types --targets=latest
./bin/wpx test unit integration --targets=latest,min --edition=both
```

Anything touching rewrite rules, blocks, REST or multisite also needs `./bin/wpx test e2e`.

## Blocks

Sources are TypeScript under `plugins/<slug>/blocks/<block>/`, built with Vite into `build/`.
Adding a block means adding a directory with a `block.json` - the PHP module registers whatever it
finds, so no PHP changes are needed.

Three patterns ship as examples: a dynamic block (`render.php`), a static block with a
`deprecated` entry, and an InnerBlocks container. See `docs/blocks.md`.

**Never change a static block's `save()` without adding a `deprecated` entry.** The old markup is
already stored in people's posts; without the entry every existing post shows the block as invalid.
An e2e test enforces this.

`index.asset.php` is generated by the build. Never edit it by hand.

## Themes

Blocks behave differently under block themes and classic themes, so the e2e suite sweeps several.
Configure them in `wp-matrix.json` under `themes`; local themes go in `themes/<slug>/`.

```bash
./bin/wpx theme list
./bin/wpx theme use tt1          # switch to the classic theme
./bin/wpx test e2e --themes=tt1
```

## Free and Pro editions

`plugins/<slug>/` is the free plugin, `plugins/<slug>-pro/` a paid add-on that extends it **only**
through public hooks (`<prefix>_modules`, `<prefix>_register_modules`, `<prefix>_rest_item`,
`<prefix>_settings_defaults`). Reaching into the free plugin's internals from the add-on is a bug.

When the extension contract changes, bump `Core\Api::VERSION` in the free plugin and the matching
`*_PRO_MIN_CORE_API` constant in the add-on.

## Releasing

```bash
./bin/wpx version 1.2.0            # every place the version is written down
./bin/wpx build --edition=both --verify
```

`--verify` unpacks the zip on a running site and activates it. **Never run `wp plugin install`
against a mounted plugin directory** - WordPress deletes the target directory before unpacking,
which destroys the working copy on the host.

## Staying current

```bash
./bin/wpx skills update    # official WordPress agent skills in .claude/skills
./bin/wpx skills global    # this repo's own skills into ~/.claude/skills - ask the user first,
                           # it writes outside the repository
./bin/wpx upgrade          # the lab tooling itself, from the starter repository
```

Both require a clean git tree for `upgrade`, and both leave their changes as a reviewable diff.

## Removing what you do not need

```bash
./bin/wpx feature list
./bin/wpx feature remove blocks     # or settings, rest, cli, content-type
./bin/wpx feature add blocks        # restores it
```

Removing a feature deletes its code, its tests and its registry entry, and reports which npm
packages became unused.
